### 1. Confirmed server bug: ownership incorrectly closes ordinary terrain

`$CTPSERVER/internal/gameplay/rules/retail_runtime.go::ProjectRetailRuntime` initializes `RuntimeMovement{OpenAccess:false}`. `engine/units.go::canAccessTile` then permits only unowned/self-owned tiles or `OpenAccess && tile.Open`. Both `moveUnit` and `retained_movement.go::advanceMovementOrder` use that gate. `visibility/visibility.go::planningTiles` separately repeats the same ownership condition, causing the client to receive an actual denial. AI city founding between turns legitimately assigns these nearby owners; ownership itself is not evidence that the terrain must be impassable.

Released authority: `ctp2_source/ctp2_code/gs/world/cellunitlist.cpp::CanEnter` (37–96) tests movement environment/road/domain; `CanMoveIntoCell` (495–545) tests stack limit, terrain entry, ZOC, foreign-city capture and ceasefire/pact restrictions. **Ordinary foreign-owned empty terrain is not a closed border.** Do not confuse that with a settler being allowed to capture a foreign city.

**Server fix:** correct the retail access policy, separating ordinary foreign-terrain entry from city/occupant/treaty restrictions. Under the current narrow boolean model, enabling retail `OpenAccess` admits the generated `Open:true` ordinary tiles, but that is only a candidate policy change until city/garrison/cargo/war tests establish its safety. Share one eligibility policy between immediate movement, retained movement and viewer planning; do not merely turn the client's false into true, remove owners, delete cities or blanket-authorize foreign cities. Rules are immutable per game: changing the retail compiler alone fixes new pins, not existing game95. Maintainer must provide a versioned supported compatibility/migration policy; no ad-hoc DB edits.

### 2. Confirmed independent server bug: missing released first-move allowance

The fresh settler allowance100 and forest cost200 are correct retail-scale values, not a units mismatch. Neutral `(3,5)` passes domain/access but `engine/units.go::moveUnit` rejects `remaining < cost`. `retained_movement.go::advanceMovementOrder` goes further: because even refreshed allowance100 is less than200, it marks the step `impossible`, stops and drops the order. The same affects desert/hills and more expensive jungle/swamp/mountains even after correcting ownership. Client `is_passable` already allows this neutral forest intention; it cannot make the server execute it.

Released authority: `UnitData.cpp::IsMovePointsEnough` (802–819) unconditionally permits `k_UDF_FIRST_MOVE`; `ResetMovement` (591–625) sets it, construction sets it near273, and `DeductMoveCost` (531–539) clears it and clamps remaining points to0 after subtracting terrain cost. `cellunitlist.cpp::IsMovePointsEnough` (547–577) skips the cost comparison for **each member** on its first move. `ArmyData.cpp::Move` (5195) and `DeductMoveCost` (6482–6506) wire those actual admission/deduction calls. These are original released files, not Apolyton behavior.

**Server fix:** persist an explicit per-unit first-move-this-turn fact (creation/refresh true; appropriate successful movement/action consumption false), use it per army member in one shared step-admission/spend helper, permit the expensive first step and saturate movement to0. After a first cheap step, insufficient remaining points must still defer/reject the next expensive step; do not allow every positive-budget move or infer unused-first-move from `movement == max_movement`. Retained execution must wait for next turn's first-step allowance instead of declaring such legal terrain permanently impossible. Preserve fuel, domain, ZOC, stack, city, ownership-policy and phase safeguards independently. Update projection/action planning and AI to the same policy, including `visibility.go` cost-budget filters/`Plan`; keep unknown first-move state unavailable rather than a client guess. Persist/hash/replay the new fact deterministically, with explicit legacy-save policy. Existing `engine/automation_review_test.go::TestRetainedMovementDoesNotWaitForeverForImpossibleTerrainCost` codifies the current generic unaffordable-stop behavior; retail first-move cases must no longer be conflated with genuinely illegal terrain.
